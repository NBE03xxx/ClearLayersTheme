# Clear Layers v1.2.3

[README に戻る](../../README.md)

2026-11-23 に、CSSキャッシュの更新対策と検索結果の修正を含めて同じ v1.2.3 を再公開しました。既存の v1.2.3 タグも今回のコミットへ更新しています。

## サイトブランディングの配置と幅

テーマ設定の「Settings」に「サイトブランディングの配置」と「サイトブランディングの幅（％）」を追加しました。ロゴ・サイト名・スローガンのまとまりを左・中央・右に配置し、親要素に対する幅を1〜100％の整数で指定できます。新規インストールの初期値は左寄せ・100％です。

- Drupal のサイトブランディングブロック、Canvas に置いた同じブロック、「ロゴ・サイト名（手入力）」SDC に共通で適用します。
- 既存の「ロゴの右／下に文字を表示」と併用できます。ロゴの表示・非表示や独自画像の設定を維持します。
- ヘッダー内では、検索・表示切り替えなどの操作部品に必要な幅を残し、空いている領域をブランディングに割り当てます。100％でも狭い列の中に制限され、右に余白を残したままサイト名が折り返される問題を解消します。
- テーマ設定を保存すると、ヘッダー側の「ブランディングの幅」「ブランディングの表示位置」より優先します。狭い画面でも指定した割合と配置を保ち、必要に応じて文字を折り返します。
- 設定変更時にキャッシュされたHTMLも更新されるよう、テーマ設定への依存を保持します。

詳しい設定例は [ブランディングの配置と幅](../theme-settings.md#サイトブランディングの配置と幅)を参照してください。

## CSSキャッシュの更新対策と検索結果の修正

CSSファイル本体を更新しても古い集約CSSが配信され、記事や固定ページなどで以前のヘッダー幅が使われる場合に対応しました。テーマ自身とSDCのローカルCSS・JavaScriptの内容からライブラリのバージョンを生成し、ライブラリのバージョンを集約ファイルの識別に使うDrupalでも、内容の更新を反映できるようにします。外部CDNや他テーマ・モジュールのライブラリは変更しません。

併せて、320px幅の検索結果ページで、抜粋中の長いURL・ファイルパスがページ全体を横にはみ出す問題を修正しました。

更新後のキャッシュ再構築が必要です。ブランディングの配置・幅がすでに保存済みの場合、設定を保存し直す必要はありません。

## 開発ツールの整理

Gulp・Webpack・Babel・PostCSS・ESLint・Stylelint の設定と開発環境の設定例を `tools/` にまとめました。`npm run build`、`npm run watch` などの npm コマンドは従来どおりテーマ直下で実行します。詳細は [開発と検証](../development.md)を参照してください。

## v1.2.0〜再公開前の v1.2.3 からの更新

テーマファイルを v1.2.3 に更新します。Git で `main` を追跡している場合は、テーマディレクトリで `git pull --ff-only origin main` を実行します。続けて Drupal プロジェクト直下でキャッシュを再構築します。

```sh
vendor/bin/drush cr
```

タグを指定して利用する場合は、今回更新した v1.2.3 タグをテーマディレクトリで取得してからチェックアウトしてください。以前ダウンロードしたZIPを使用している場合も、GitHubから取得し直します。

```sh
git fetch origin +refs/tags/v1.2.3:refs/tags/v1.2.3
git checkout v1.2.3
```

タグから更新した場合も、Drupalプロジェクト直下で `vendor/bin/drush cr` を実行します。

新しい配置・幅が未保存の場合は、「外観 → Clear Layers の設定」（`/admin/appearance/settings/clear_layers`）の「Settings」で選択して保存します。ヘッダーの空いている幅を使う場合は100％を指定してください。すでに保存済みの場合は再保存不要です。

既存サイトで新しい配置・幅が未保存の場合は、従来の表示を維持します。保存済みのCanvasコンポーネントのID・props・slotsは変更しないため、コンポーネントの移行、ページテンプレートの作り直し、設定の一括インポート、依存パッケージの追加は不要です。ビルド済みCSS・JavaScriptを同梱しているため、利用時の再ビルドも不要です。

v1.2.0 / v1.2.1 で Gin Login の補正も適用する場合は、[v1.2.2 の更新手順](v1.2.2.md#v120--v121-からの更新)も確認してください。v1.1.5以前から更新する場合は、先に [更新専用の手順](../upgrade-from-v1.1.5.md)を確認してください。

## 検証範囲

Drupal 11.4.13 / Canvas 1.13.0 のサイトで、次を確認しました。

- 配置3種類・幅1％／50％／100％・ロゴと文字の右／下配置の18通り、設定フォームの値と保存用の整数変換、不正値と範囲制約、HTMLのキャッシュ依存。
- 新しい配置・幅が未保存の既存サイトで、従来の表示を維持すること。
- Chromium の1440px・1024px・768pxで、幅100％のブランディングが利用可能な領域全体を使い、検証サイトのサイト名が1行になること。
- 390px・320pxで、操作部品との重なりやページの横はみ出しがなく、長いサイト名を折り返せること。
- 幅50％で左・中央・右への配置と幅の計算が正しいこと。
- トップ・個別記事・固定ページ・案内・検索結果・分類一覧・404を含む、ログアウト時45通りとログイン時の出力35通りで、5つの画面幅のブランディングに重なりや横はみ出しがないこと。
- 長いファイルパスを含む検索結果でも、320px幅で横にはみ出さないこと。
- CSS・JavaScriptの内容変更にライブラリのバージョンが追従し、更新日時だけの変更では変わらないこと。SDCの相対パス・外部ライブラリ・他の拡張の扱いも確認しました。
- 標準ロゴの自動・手動選択、独自ロゴ・非表示設定、Drupal／Canvasでの描画。
- 42個のSDC定義・Twigと106個のDrupal Twigテンプレートを読み込めること。
- 読み取り検証の前後で、保存済みのテーマ設定が変わらないこと。

実行コマンドと前提条件は [開発と検証](../development.md)を参照してください。
