# Clear Layers v1.1.1

Blank などから Canvas を使うサイトを新しく構成するための初期設定を追加しました。共通ヘッダー・フッターの編集プレビューが二重になる問題を修正し、新しいフッターメニューブロックを1階層で配置できるようにしました。

## 変更内容

- テーマ設定に「Canvas の初期構成を作成」ボタンを追加。共通ヘッダー・フッターのパターンと「サイト共通レイアウト」「分類・タグの一覧」テンプレートを生成します。既定テンプレートの変更はチェック項目で選べます。
- 同梱の補助モジュールをテーマ内から検出・有効化し、分類・タグのページに専用テンプレートを適用します。利用者によるモジュールファイルのコピーは不要です。
- 共通パターンの編集プレビューを、そのパターンの内容だけで表示。既定のページレイアウトが重なってヘッダー・フッターが二重になる問題を修正しました。部品を選択するための情報は保持します。
- 初期構成のフッターメニューと、新しく配置する標準「フッター」ブロックの開始階層・表示階層を1に設定。Canvas の階層フォームの検証エラーを避けます。ヘッダーの専用ナビゲーションは無制限のままです。
- 記事カードの投稿日表示を、記事本文の日時表示と同じ書式に揃えました。
- README に、テーマ導入後に初期ページを `/home` として保存してから Canvas の初期構成を実行する手順を追加。既存 Canvas テーマからの移行と、新規導入を区別し、不要になった Blank の整理手順も記載しました。
- スターターキットの書き出しに、フッターメニューの初期値を提供する補助モジュールのファイルも含めました。

## 更新方法

テーマのファイルを更新し、Drupal プロジェクト直下で実行してください。

```sh
vendor/bin/drush cr
```

テーマの再インストールや、設定の一括インポートは不要です。既存のページ・パターン・テンプレート・保存済みメニュー階層は保持します。

新規サイトでは [README の新規導入手順](https://github.com/NBE03xxx/ClearLayersTheme/blob/v1.1.1/README.md#新規サイトの-canvas-初期構成)に従ってください。初期構成には Canvas 1.12 以降の1.x・Taxonomy・Views が必要です。ページ・記事・コンテンツタイプ・分類・Views は、サイトに合わせて別途用意します。

標準「フッター」ブロックの新規配置時の初期値を1にするには、同梱の Clear Layers Canvas Taxonomy を有効にします。新規導入では初期構成ボタンが有効化します。既存サイトで初期構成ボタンを使わず、この初期値だけを利用する場合は、次のコマンドで有効化できます。

```sh
vendor/bin/drush en clear_layers_canvas_taxonomy -y
vendor/bin/drush cr
```

補助モジュールは分類ページにも既存の `taxonomy_listing` テンプレートがあれば適用します。既存サイトで有効化する場合は、そのテンプレートの内容を確認してください。初期構成ボタンは、旧テーマの部品参照やページ内のヘッダー・フッターを移行する機能ではありません。Byte・Mercury などからの移行は [移行ガイド](https://github.com/NBE03xxx/ClearLayersTheme/blob/v1.1.1/docs/migration.md)を参照してください。

## 検証

- 新規生成するパターン・テンプレート4件の Canvas 検証、初期構成の再実行時の既存設定保持、テーマ設定のボタンと編集リンク、管理権限を確認しました。
- ヘッダー・フッターのパターン編集 API で、編集対象が1個だけ表示され、部品選択情報と編集モデルが一致することを確認しました。テンプレート編集と公開 Home のヘッダー・フッターも確認しました。
- 実際の Drupal メニューブロックの設定フォームと、Canvas が Library からの新規配置に使う保存済み初期値を確認しました。明示的に保存した階層値と、ヘッダーの無制限設定が保持されることも確認しました。
- Canvas の設定・コンテンツ・過去のリビジョンの整合性診断は、検証エラーなしでした。
- 利用者による別サーバーでの新規導入・編集プレビュー・フッターメニューの動作確認が完了しました。
