# 新規サイトの Canvas 初期構成

[README に戻る](../README.md)

この手順は、v1.2.0の Clear Layers を初めて適用し、Blank などから Canvas のページを新しく作る場合が対象です。Canvas を使わない場合は、[テーマのインストール](../README.md#インストール)だけで利用できます。v1.1.5以前の旧バージョンで作成済みの構成を更新する場合は、[更新専用の手順](upgrade-from-v1.1.5.md)を使用してください。

## 1. Canvas とテーマを導入する

[インストール手順](../README.md#インストール)でテーマを配置し、Twig Field Value・Twig Tweak を有効にします。Canvas が未導入なら、Drupal プロジェクト直下で追加します。初期構成には **Canvas 1.12 以降の 1.x、Taxonomy、Views** が必要です。

```sh
composer require 'drupal/canvas:^1.12'
vendor/bin/drush en canvas taxonomy views twig_field_value twig_tweak -y
vendor/bin/drush theme:install clear_layers -y
vendor/bin/drush config:set system.theme default clear_layers -y
vendor/bin/drush cr
```

導入済みの拡張については、その手順を省略できます。管理画面では「機能拡張」で各モジュールを有効にし、「外観」で Clear Layers を既定テーマにします。管理者は、テーマ・モジュール・Canvas の部品・ページテンプレートを管理する権限が必要です。

## 2. 最初のページを `/home` として保存する

Blank の初期ページを使う新規サイトでは、テーマのインストールと既定テーマへの切り替えが終わったら、共通構成を作る前に最初のページを確認します。

1. `/page/1` を開き、「編集」から Canvas の編集画面を開きます。直接開く場合は `/canvas/editor/canvas_page/1` です。
2. 右側の **「Page data」** にある **「URL エイリアス」** に `/home` を入力します。必要に応じてページのタイトルも `Home` にします。
3. 変更を保存し、公開操作が必要な場合は変更を公開します。
4. `/home` を開けることと、Canvas の編集画面を利用できることを確認します。

`1` は Blank の初期ページ ID の例です。`/page/1` が存在しない場合は「コンテンツ → ページ」（`/admin/content/pages`）で実際のページを確認するか、Canvas で新しいページを作り、そのページに `/home` を設定します。既存ページに別名がある場合は、用途を確認してから変更してください。

## 3. テーマ設定のボタンで共通構成を作る

1. 「外観 → Clear Layers の設定」（`/admin/appearance/settings/clear_layers`）を開きます。
2. **「Canvas の初期構成」** を開きます。
3. 新規サイトでは **「『サイト共通レイアウト』をサイトの既定テンプレートにする」** にチェックします。
4. **「Canvas の初期構成を作成」** をクリックします。「設定を保存」とは別の操作です。

同じテーマ設定画面にある「Drupal Canvas → Use Drupal Canvas for page templates in this theme.」はオフのままにします。「Canvas の初期構成」から作る共通レイアウトを使用します。

ボタンは次の構成を作成し、その場で公開済みの設定として保存します。

| 種類 | 表示名 / ID | 初期内容・用途 |
| --- | --- | --- |
| ページテンプレート | サイト共通レイアウト / `site_layout` | 直接編集できるヘッダー・ナビゲーション → Page content → 直接編集できるフッター |
| 補助モジュール | Clear Layers Canvas Taxonomy | 新規フッターメニューブロックの表示階層を1にする。分類ページもサイトの既定レイアウトを利用 |
| 補助モジュール | Canvas Library Display | Library の Components タブで、配置できる部品が0件のフォルダーを非表示にする |

補助モジュールはテーマ内の `starter-kit/modules/clear_layers_canvas_taxonomy` と `starter-kit/modules/canvas_library_display` から Drupal が検出し、ボタンが一緒に有効化します。利用者によるファイルのコピーは不要です。Canvas 本体は、あらかじめ導入・有効化してください。既存のメニュー設定は保持します。

Canvas Library Display は画面上の表示だけを調整し、フォルダーや無効なコンポーネントの登録データを削除しません。配置できる部品が増えたフォルダーは自動で再表示されます。初期構成済みのサイトでも、対象の下書きなどを整理してからボタンを再実行すると、既存の構成を保持して追加の補助モジュールを有効化できます。

v1.1.5以前の旧バージョンで `web/modules/custom/canvas_library_display` に同名モジュールを配置している場合は、そのディレクトリをサイト外へ退避して同梱版だけにし、キャッシュを再構築してください。有効化済みの場合、アンインストールは不要です。Canvas の画面も再読み込みしてください。

既存の同じ ID のテンプレートは上書きしません。v1.1.5以前の旧バージョンのパターン参照を使っている場合は、[更新専用の手順](upgrade-from-v1.1.5.md)で移行してください。対象に未公開の変更がある場合や、無効・検証エラーのある構成がある場合は、Canvas で公開・修正または下書きを破棄してから再実行します。途中で失敗した場合も、既存の内容を上書きせず、不足する構成を再実行で補えます。必要な部品だけをライブラリで有効にし、他テーマのページ・部品の参照は変換しません。

初期構成の実行後は、次の順で `/home` を整理します。

1. `/home` の Canvas 編集画面を開き直し、部品ライブラリ（Library）に Clear Layers の部品があることを確認します。
2. Home に適用するページテンプレートを確認します。サイトの既定が「サイト共通レイアウト」であれば、**「Site Default」のままで利用できます**。別テーマのテンプレートが明示設定されている場合は、「Site Default」または「サイト共通レイアウト」に変更します。
3. Home の本文側（Page content 内）に配置済みのヘッダー・ナビゲーション・フッターがあれば削除します。共通部品の参照も対象です。Hero・本文・記事一覧など、ページ固有の内容は残します。テンプレート側の共通ヘッダー・フッターは保持してください。
4. 変更を保存・公開し、`/home` でヘッダー・フッターが各1個だけ表示されることを確認します。

## 4. 共通ヘッダー・フッターを編集する

詳しい部品の配置方法は [共通フッターとメニュー](footer.md)を参照してください。

Canvas の「Templates → Page templates → サイト共通レイアウト」を開きます。直接開く場合は `/canvas/editor/page_variant/site_layout` です。ヘッダー、ナビゲーション、フッターとその内部の部品を、この画面で選択・編集して公開します。利用する通常ページへ一括反映されます。

メインメニューの項目は `/admin/structure/menu/manage/main`、サイトロゴはテーマ設定で変更します。`Page content` は1つ保持してください。ここに各ページの本文・一覧が表示されます。

初期構成はサイト固有のメニュー項目・記事・画像を複製しません。フッターに分類一覧を置く場合は、先に分類と Views を用意してから対応する部品を追加してください。

## 5. ページ・記事を作る

- **Home などの Canvas ページ**：前項で用意した `/home` に Hero や本文などを配置します。他のページは Canvas で追加します。サイトの既定が「サイト共通レイアウト」であれば、ページテンプレートは「Site Default」のままで利用できます。個別に「サイト共通レイアウト」を選択することもできます。共通ヘッダー・フッターはテンプレートから表示されるため、ページ内に追加する必要はありません。各ページに URL 別名を設定し、公開します。
- **リンク集・サイト方針などの案内ページ**：[案内ページコンポーネント](information-page.md)をページの本文領域に配置し、見出しと本文を追加します。初期構成ボタンは案内ページを自動作成しません。
- **トップページ**：「設定 → システム → サイトの基本設定」（`/admin/config/system/site-information`）のデフォルトのフロントページに、作成したページの URL を指定します。
- **Drupal の記事**：利用するコンテンツタイプとフィールドを先に用意します。Canvas の全文用コンテンツテンプレートを設定し、ページテンプレートに「サイト共通レイアウト」を選びます。一覧カードの表示は別途、表示モードやコンテンツテンプレートで設定します。
- **分類・タグのページ**：語彙・分類・記事との参照フィールドを用意し、「構築 → Views」（`/admin/structure/views`）で **Taxonomy term** の一覧を確認・有効化します。分類のリンク `/taxonomy/term/{ID}` は「サイト共通レイアウト」の Page content に一覧を表示します。URL 別名がある場合も同じです。分類名・パネルはテーマの `templates/views/views-view--taxonomy-term--page-1.html.twig`、件数・絞り込み・並び順・カードの表示モードは Views で編集します。検索結果も一覧側の設定と Twig で管理し、共通の外枠は変更しません。

ボタンで作成するのは「サイト共通レイアウト」です。Home、コンテンツタイプ、フィールド、記事、分類、Views、URL 別名は上記の手順でサイトに合わせて設定します。生成後は、PC・スマホ幅で Home・記事・分類ページと Canvas の編集・公開を確認してください。

## 6. 不要になった Blank テーマを整理する（任意）

Clear Layers は親テーマを必要としないため、Blank を残しておく必要はありません。初期構成の作成と表示・編集の確認が済み、Blank を使う構成がなければ、次の順で整理できます。

1. Clear Layers が既定テーマであることと、Blank が管理テーマや他テーマの親テーマとして使われていないことを確認します。
2. Blank で作成した Canvas のページ・テンプレート・パターンがある場合は、下書き・過去のリビジョンも含めて Blank の部品への参照を確認します。参照が残る場合は、[移行ガイド](migration.md)に沿って移行・検証してから進めます。
3. 「外観」（`/admin/appearance`）で **Blank の「アンインストール」** を選択します。依存する設定の削除が表示された場合は内容を確認し、必要な構成が含まれる場合は中止します。
4. 再度、公開ページと Canvas の編集・公開を確認します。テーマのファイルも整理する場合は、この確認後に行います。Composer 管理の場合は実際のパッケージ名と依存関係を確認して削除し、手動配置の場合はアンインストール済みのテーマディレクトリを削除します。

既定テーマの切り替えと、Drupal でのアンインストール、テーマファイルの削除は別の操作です。Blank を残したまま Clear Layers の新規導入テストを進めることもできます。
