# Clear Layers Canvas Taxonomy

Clear Layers で標準「フッター」メニューブロックを新しく配置するとき、開始階層・表示階層を1にし、管理テーマのページに公開側の Canvas レイアウトが混入するのを防ぐ補助モジュールです。v1.1.5以前の旧バージョンにあった、分類・タグページへの専用の外枠の割り当ては廃止しました。通常ページはサイトの既定「サイト共通レイアウト」を利用します。

Gin Login が管理テーマで表示するログイン・パスワード再設定画面などは、管理テーマ本来のページテンプレートを使用します。Canvas 1.12 の既定テンプレートがこれらの画面にも適用される場合に、管理テーマ使用時の Canvas によるページ描画だけを Core の通常描画へ戻します。Clear Layers が既定テーマである場合に限って動作し、公開ページと Canvas の編集プレビューのテンプレート選択は保持します。既存サイトへのこの修正の反映は `vendor/bin/drush cr` のみで、設定変更は不要です。

Clear Layers が既定テーマの間は、標準の「フッター」メニューブロックを新しく配置するときの表示階層を1にします。開始階層も標準の1なので、Canvas の階層フォームで無制限と未展開の組み合わせによるエラーを避けられます。保存済みの階層は保持し、ヘッダーのメニューや他モジュールが提供する独自のメニューブロックは変更しません。

新規導入では、テーマ設定の **「Canvas の初期構成を作成」** がこのモジュールを有効化します。モジュールはテーマ内のこのディレクトリから Drupal が検出するため、別の場所へのコピーは不要です。詳しくは [新規導入手順](../../../README.md#新規サイトの-canvas-初期構成)を参照してください。

Clear Layers の v1.1.5以前の旧バージョンを使用しているサイトは、[更新手順](../../../docs/upgrade-from-v1.1.5.md)を実行してください。

v1.1.5以前の旧バージョン由来の、未使用の「Clear_layers theme」の削除と PageRegion の無効化も同文書に掲載しています。このモジュールはフッターメニューブロックの初期値を引き続き担当するため、共通レイアウトに移行した後も使用します。

テーマのコード一式を削除する場合は、その前に「機能拡張 → アンインストール」でこの補助モジュールをアンインストールしてください。モジュールのコードもテーマ内にあるため、有効なままテーマディレクトリを削除しないでください。

- メニューの URL 別名とタグのリンクは従来のままです。
- 元の Views 一覧を共通レイアウトの `Page content` の位置に表示します。絞り込み、アクセス制御、ページャー、RSS は Views が処理します。
- ヘッダー・フッターは「サイト共通レイアウト」で直接編集します。
- 分類名とパネルは `templates/views/views-view--taxonomy-term--page-1.html.twig` が SDC を利用して表示します。ブロック・RSS 表示には適用しません。
- 一覧のカード内容は、そのサイトで使う表示モードまたは Canvas のコンテンツテンプレートで編集します。件数、絞り込み、並び順は Views の設定です。
- ページテンプレートは Canvas 標準の選択処理に従います。

公開用 URL 例: `/drupal`、`/taxonomy/term/2`。
共通レイアウト編集 URL: `/canvas/editor/page_variant/site_layout`。

Core / Canvas 更新時には、メニューブロックの初期値、Views の描画、Gin Login の画面を検証してください。ログイン画面の読み取り検証と前提条件は [開発と検証](../../../docs/development.md)を参照してください。Core / contrib の直接変更は不要です。
