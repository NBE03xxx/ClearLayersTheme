# Clear Layers

Drupal 11 用の、半透明のパネル・柔らかなぼかし・重なりによる奥行きを備えた独立したカスタムテーマです。Drupal Core Starterkit を基礎とし、親テーマを必要としません。

![Clear Layers の標準背景](background/blue-glowing-waves.png)

- 機械名: `clear_layers`
- バージョン: `1.1.1`
- 検証環境: Drupal 11.4.9 / Canvas 1.12.0
- 親テーマ: なし（`base theme: false`）

v1.1.1 では、Canvas の新規導入用の初期構成ボタンを追加し、共通パターン編集時の二重表示とフッターメニューの初期値を修正しました。変更内容と更新時の扱いは [リリースノート](docs/releases/v1.1.1.md) を参照してください。v1.1.0 で追加した同梱背景と12種類の配色も引き続き利用できます。

## 導入方法を選ぶ

導入方法は、次のどちらかを選んでください。

- **Blank などを使う新規サイトで Canvas の構成を作る**：[新規サイトの Canvas 初期構成](#新規サイトの-canvas-初期構成)へ進みます。テーマ設定のボタンで共通パターンとテンプレートを用意できます。
- **Byte・Mercury などで作った Canvas ページがある**：[移行ガイド](docs/migration.md)へ進みます。初期構成ボタンは、保存済みのページや旧テーマの部品を移行する機能ではありません。Blank でも既存の Canvas 構成がある場合はこちらです。

Byte・Mercury などの Canvas 対応テーマからの移行は、Codex CLI などの生成AIを活用し、実際のサイト構成に合わせて調査・実装・検証を進めることを前提に案内しています。**移行作業を始める前に、[migration.md](docs/migration.md) をよく読んでください。**

ガイドには、SSH と Codex CLI を使う作業環境の例、`AGENTS.md` の記述例、移行と不要な関連ファイルの整理を依頼するプロンプト例を掲載しています。環境に合わせて調整し、バックアップ・保持するデータ・変更範囲を確認してから進めます。後半には、AIが提示した計画の確認にも使える手動手順を参考として記載しています。

## 主な機能

- 青・緑・赤・琥珀色・モノクロをもとにした配色、透過、背景のぼかし、奥行き。
- 基調色がわかる12種類の配色、同梱の背景画像、左右余白・ブロック間隔をテーマ設定で調整。
- 訪問者の OS 設定に従う明暗モードと、小さな切り替えボタン。
- Canvas で利用できる SDC。ナビゲーション、ヘッダー、フッター、Hero、記事ヘッダー、カード、本文、一覧など。
- ブログ本文・コードブロックの明暗対応、長いコードの横スクロール。
- カード全体を通常のリンクとしてクリック可能。キーボード・Ctrl／中クリックに対応。
- サイト共通ヘッダー・フッターを Canvas パターンから参照する部品。
- テーマ設定の折りたたみプレビュー。
- 小さい画面では高さを抑えたヘッダーと、アイコンで開閉する検索パネル。
- テーマの配色と質感に合わせた公開操作パネル・ステータスメッセージ。

## インストール

通常のカスタムテーマと同様に、ファイルをテーマディレクトリへ配置し、管理画面からインストールできます。ビルド済み CSS・JavaScript を含むため、利用するだけなら Node.js は不要です。

以下は通常の導入例です。既存の Canvas 対応テーマから移行する場合は、先に [migration.md](docs/migration.md) に沿って移行計画を確認してください。既定テーマの変更だけでは、Canvas の保存済みコンポーネント参照やブロック配置は移行されません。

Drupal プロジェクト直下で実行する例:

```sh
git clone https://github.com/NBE03xxx/ClearLayersTheme.git web/themes/custom/clear_layers
composer require 'drupal/twig_field_value:^2.0' 'drupal/twig_tweak:^3.2'
```

1. 管理画面の「機能拡張」（`/admin/modules`）で **Twig Field Value** と **Twig Tweak** を有効にします。
2. 「外観」（`/admin/appearance`）で **Clear Layers** を「インストールしてデフォルトに設定」します。
3. 「設定」（`/admin/appearance/settings/clear_layers`）で配色・背景・余白などを調整します。

Drush を使う場合:

```sh
vendor/bin/drush en twig_field_value twig_tweak -y
vendor/bin/drush theme:install clear_layers -y
vendor/bin/drush config:set system.theme default clear_layers -y
vendor/bin/drush cr
```

公開ディレクトリが `web` 以外の場合は、そのディレクトリ内の `themes/custom/clear_layers` に配置してください。GitHub の ZIP を使う場合も、展開したディレクトリ名を `clear_layers` にします。

## 新規サイトの Canvas 初期構成

この手順は、Blank などを使っているサイトに Clear Layers を導入し、これから Canvas のページを作る場合の手順です。Canvas を使わない場合は、前項のテーマのインストールだけで利用できます。

### 1. Canvas とテーマを導入する

前項の手順でテーマを配置し、Twig Field Value・Twig Tweak を有効にします。Canvas が未導入なら、Drupal プロジェクト直下で追加します。初期構成には **Canvas 1.12 以降の 1.x、Taxonomy、Views** が必要です。

```sh
composer require 'drupal/canvas:^1.12'
vendor/bin/drush en canvas taxonomy views twig_field_value twig_tweak -y
vendor/bin/drush theme:install clear_layers -y
vendor/bin/drush config:set system.theme default clear_layers -y
vendor/bin/drush cr
```

導入済みの拡張については、その手順を省略できます。管理画面では「機能拡張」で各モジュールを有効にし、「外観」で Clear Layers を既定テーマにします。管理者は、テーマ・モジュール・Canvas の部品・パターン・ページテンプレートを管理する権限が必要です。

### 2. 最初のページを `/home` として保存する

Blank の初期ページを使う新規サイトでは、テーマのインストールと既定テーマへの切り替えが終わったら、共通構成を作る前に最初のページを確認します。

1. `/page/1` を開き、「編集」から Canvas の編集画面を開きます。直接開く場合は `/canvas/editor/canvas_page/1` です。
2. 右側の **「Page data」** にある **「URL エイリアス」** に `/home` を入力します。必要に応じてページのタイトルも `Home` にします。
3. 変更を保存し、公開操作が必要な場合は変更を公開します。
4. `/home` を開けることと、Canvas の編集画面を利用できることを確認します。

`1` は Blank の初期ページ ID の例です。`/page/1` が存在しない場合は「コンテンツ → ページ」（`/admin/content/pages`）で実際のページを確認するか、Canvas で新しいページを作り、そのページに `/home` を設定します。既存ページに別名がある場合は、用途を確認してから変更してください。

### 3. テーマ設定のボタンで共通構成を作る

1. 「外観 → Clear Layers の設定」（`/admin/appearance/settings/clear_layers`）を開きます。
2. **「Canvas の初期構成」** を開きます。
3. 新規サイトでは **「『サイト共通レイアウト』をサイトの既定テンプレートにする」** にチェックします。
4. **「Canvas の初期構成を作成」** をクリックします。「設定を保存」とは別の操作です。

ボタンは次の構成を作成し、その場で公開済みの設定として保存します。

| 種類 | 表示名 / ID | 初期内容・用途 |
| --- | --- | --- |
| 共通パターン | サイト共通ヘッダー / `site_header` | サイトロゴ・名前、明暗モード切替、メインナビゲーション |
| 共通パターン | サイト共通フッター / `site_footer` | フッターメニュー（開始階層・表示階層ともに1）とログイン・ログアウトリンク |
| ページテンプレート | サイト共通レイアウト / `site_layout` | 共通ヘッダー → Page content → 共通フッター |
| ページテンプレート | 分類・タグの一覧 / `taxonomy_listing` | 共通ヘッダー → 分類名と一覧用パネル → 共通フッター |
| 補助モジュール | Clear Layers Canvas Taxonomy | 分類・タグの公開ページに専用テンプレートを割り当て、新規フッターメニューブロックの表示階層を1にする |

補助モジュールはテーマ内の `starter-kit/modules/clear_layers_canvas_taxonomy` から Drupal が検出し、ボタンが有効化します。利用者によるファイルのコピーは不要です。Canvas 本体は、あらかじめ導入・有効化してください。旧補助モジュールがある既存サイトでも、新しい初期値を利用するために同梱モジュールを有効化します。既存のパターンやメニュー設定は保持します。

既存の同じ ID のパターン・テンプレートは上書きしません。対象に未公開の変更がある場合や、無効・検証エラーのある構成がある場合は、Canvas で公開・修正または下書きを破棄してから再実行します。途中で失敗した場合も、既存の内容を上書きせず、不足する構成を再実行で補えます。必要な部品だけをライブラリで有効にし、他テーマのページ・部品の参照は変換しません。

初期構成の実行後は、次の順で `/home` を整理します。

1. `/home` の Canvas 編集画面を開き直し、部品ライブラリ（Library）に Clear Layers の部品があることを確認します。
2. Home に適用するページテンプレートを確認します。サイトの既定が「サイト共通レイアウト」であれば、**「Site Default」のままで利用できます**。旧テーマのテンプレートが明示設定されている場合は、「Site Default」または「サイト共通レイアウト」に変更します。
3. Home の本文側（Page content 内）に配置済みのヘッダー・ナビゲーション・フッターがあれば削除します。共通部品の参照も対象です。Hero・本文・記事一覧など、ページ固有の内容は残します。テンプレート側の共通ヘッダー・フッターは保持してください。
4. 変更を保存・公開し、`/home` でヘッダー・フッターが各1個だけ表示されることを確認します。

移行時に本文内のヘッダー・フッターが残って二重表示になり、既存部品を編集できない場合は、一時的に「サイト共通レイアウト」を明示選択してから重複を整理してください。確認された事例では、この操作で削除でき、整理後は「Site Default」に戻しても編集できました。これは問題が発生した場合の回避手順で、新規導入時にテンプレートの明示指定を必須とするものではありません。

旧テーマの部品への参照がある場合は、[移行ガイド](docs/migration.md)に沿って確認・移行してください。

### 4. 共通ヘッダー・フッターを編集する

初期構成欄に表示される編集リンクから `site_header` と `site_footer` を開き、必要な部品を追加して公開します。メインメニューの項目は `/admin/structure/menu/manage/main` で追加します。サイトロゴはテーマ設定で変更します。

共通パターンの編集プレビューには、そのパターンの内容だけを表示します。たとえば共通ヘッダーを編集するときは、サイト全体のヘッダー・フッターを重ねません。公開ページと「サイト共通レイアウト」の編集画面では、共通ヘッダー・フッターを通常どおり表示します。

初期構成はサイト固有のメニュー項目・記事・画像を複製しません。フッターに分類一覧を置く場合は、先に分類と Views を用意してから対応する部品を追加してください。

### 5. ページ・記事を作る

- **Home などの Canvas ページ**：前項で用意した `/home` に Hero や本文などを配置します。他のページは Canvas で追加します。サイトの既定が「サイト共通レイアウト」であれば、ページテンプレートは「Site Default」のままで利用できます。個別に「サイト共通レイアウト」を選択することもできます。共通ヘッダー・フッターはテンプレートから表示されるため、ページ内に追加する必要はありません。各ページに URL 別名を設定し、公開します。
- **トップページ**：「設定 → システム → サイトの基本設定」（`/admin/config/system/site-information`）のデフォルトのフロントページに、作成したページの URL を指定します。
- **Drupal の記事**：利用するコンテンツタイプとフィールドを先に用意します。Canvas の全文用コンテンツテンプレートを設定し、ページテンプレートに「サイト共通レイアウト」を選びます。一覧カードの表示は別途、表示モードやコンテンツテンプレートで設定します。
- **分類・タグのページ**：語彙・分類・記事との参照フィールドを用意し、「構築 → Views」（`/admin/structure/views`）で **Taxonomy term** の一覧を確認・有効化します。分類のリンク `/taxonomy/term/{ID}` を開くと、「分類・タグの一覧」が自動で適用されます。URL 別名がある場合も同じです。件数・絞り込み・並び順は Views で編集します。

ボタンで作成するのは共通パターンとページテンプレートです。Home、コンテンツタイプ、フィールド、記事、分類、Views、URL 別名は上記の手順でサイトに合わせて設定します。生成後は、PC・スマホ幅で Home・記事・分類ページと Canvas の編集・公開を確認してください。

### 6. 不要になった Blank テーマを整理する（任意）

Clear Layers は親テーマを必要としないため、Blank を残しておく必要はありません。初期構成の作成と表示・編集の確認が済み、Blank を使う構成がなければ、次の順で整理できます。

1. Clear Layers が既定テーマであることと、Blank が管理テーマや他テーマの親テーマとして使われていないことを確認します。
2. Blank で作成した Canvas のページ・テンプレート・パターンがある場合は、下書き・過去のリビジョンも含めて Blank の部品への参照を確認します。参照が残る場合は、[移行ガイド](docs/migration.md)に沿って移行・検証してから進めます。
3. 「外観」（`/admin/appearance`）で **Blank の「アンインストール」** を選択します。依存する設定の削除が表示された場合は内容を確認し、必要な構成が含まれる場合は中止します。
4. 再度、公開ページと Canvas の編集・公開を確認します。テーマのファイルも整理する場合は、この確認後に行います。Composer 管理の場合は実際のパッケージ名と依存関係を確認して削除し、手動配置の場合はアンインストール済みのテーマディレクトリを削除します。

既定テーマの切り替えと、Drupal でのアンインストール、テーマファイルの削除は別の操作です。Blank を残したまま Clear Layers の新規導入テストを進めることもできます。

## 初期設定

`config/install/clear_layers.settings.yml` に保存した初期値を、新規インストール時に使います。

| 設定 | 初期値 |
| --- | --- |
| 配色 | 青 × シアン（オーシャンブルー） |
| 透過率 | 40% |
| ぼかし | 12px |
| 奥行き | 標準 |
| 左右余白 | 12px |
| ブロック間隔 | 24px |
| 背景 | 同梱の青い背景画像 |
| 明暗モード | 訪問者の OS 設定 |

既存サイトの保存済み設定は、テーマの更新だけでは上書きしません。テーマ設定のプレビューは初期状態では閉じており、クリックで展開します。保存済み設定と現在のトップページを表示します。

「サイト全体の配色」では、次の組み合わせを選べます。各配色にライト／ダークの定義があり、パネル・文字・リンク・ボタン・フォーム・フッターに共通で適用します。背景画像は別の設定なので、基調色に合う画像を「ページの背景画像」で選択してください。

| 基調色 | 組み合わせ |
| --- | --- |
| 青 | 青 × シアン、淡い青 × アクア、青・藍 × ラベンダー、青緑 × ミント |
| 緑 | 緑 × ミント、深緑 × 青緑 |
| 赤 | 赤 × ローズ、赤 × コーラル |
| 琥珀色 | 琥珀色 × ゴールド、琥珀色 × オレンジ |
| モノクロ | モノクロ × シルバー、モノクロ × チャコール |

背景画像は、テーマ設定の「ページの背景画像」から「同梱の背景画像から選択」を開き、サムネイル一覧の「選択」を押して指定します。青・緑・赤・琥珀色・モノクロの背景を `background/` に同梱しています。「テーマ標準の背景に戻す」で青い背景に戻せます。選択はプレビューに反映され、設定フォームを保存するとサイト全体に適用されます。メディアへの登録や追加モジュールは不要です。

`background/` 直下に PNG・JPEG・WebP・AVIF・GIF の画像を追加すると、テーマ設定の選択候補に表示されます。設定にはファイル名を保存するので、選択済み画像の名前や配置を変える場合は、テーマ設定で選び直してください。以前のメディア背景設定は、同梱画像を選んで保存するか標準背景に戻して保存するまで維持します。

### v1.1.0 への更新

テーマのファイルを更新した後、Drupal プロジェクト直下で `vendor/bin/drush cr` を実行してください。テーマの再インストールや設定の一括インポートは不要です。

テーマ設定の「サイト全体の配色」と「ページの背景画像」で、配色と画像をそれぞれ選んで保存します。既存の青系配色の設定 ID は維持しているため、更新だけで選択済みの配色が変わることはありません。メディアから新しい背景を選択する機能は、同梱画像の選択に置き換わります。以前のメディア背景は表示を継続し、同梱画像を選ぶか標準背景に戻して保存した際に切り替わります。

## Gin のメディアプレビュー補正と更新時の扱い

Drupal 11.4.9／Gin 5.0.15 の組み合わせでは、通常の記事編集画面の Featured image やメディアグリッドのプレビュー枠が縦長になることがあります。[補正 CSS](css/gin-media-library.css)を Gin の `public://gin-custom.css` に追加すると、正方形の表示枠になります。配置手順は [migration.md の該当項目](docs/migration.md#gin-のメディアプレビューが縦長になる場合)を参照してください。Clear Layers のインストールだけでは、この補正は適用されません。

**Core・Gin の更新によって、補正なしでも正常に表示されることを確認できるまでは補正を維持してください。** Core を更新しただけで解消するとは限らず、Gin 側の対応が必要になる可能性もあります。対応バージョンは未確認です。補正ファイルは通常の Core・Gin 更新では上書きされません。

更新後は検証環境でこの補正ルールだけを一時的に外し、Featured image、メディアグリッド、メディア選択ダイアログを PC・スマホ幅で確認します。正方形の表示が維持されれば補正を削除でき、再び縦長になる場合は補正を戻して維持します。既存の `gin-custom.css` にある他のカスタマイズは残してください。

## 記事編集画面で段落をインデントする場合

通常の文章・段落にインデントを追加・解除するには、拡張モジュール [CKEditor IndentBlock](https://www.drupal.org/project/ckeditor_indentblock) の追加・有効化が必要です。Drupal Core の CKEditor 5 に段落インデントのコードは含まれていますが、Drupal 標準ではリストのインデントのみ有効になっています。テーマを更新するだけでは、段落インデントは有効になりません。

Drupal プロジェクト直下で実行します。

```sh
composer require 'drupal/ckeditor_indentblock:^1.1'
vendor/bin/drush en ckeditor_indentblock -y
vendor/bin/drush cr
```

管理画面の「テキストフォーマットとエディター」（`/admin/config/content/formats`）で、記事本文に使うテキストフォーマットを編集します。CKEditor 5 のツールバーに「インデント」「インデント解除」を配置し、プラグイン設定の段落インデントを有効にして保存してください。ボタンが配置済みなら、同じボタンをそのまま利用できます。

HTML の許可タグを制限している場合は、モジュールが使う `<p class="Indent*">` を許可してください。モジュールが表示用 CSS を提供し、保存した段落のインデントを編集画面と公開ページに表示します。編集画面を再読み込みし、段落内にカーソルを置いて追加・解除を確認してください。

このモジュールは段落インデントを利用する場合に必要で、テーマ自体の必須依存ではありません。箇条書き・番号付きリストの表示修正は、テーマの更新で適用されます。

## 自鯖ロゴ

背景透過の「自鯖」ロゴを `images/branding/jisaba-life-logo-v2.png` に同梱しています。使う場合は、テーマ設定（`/admin/appearance/settings/clear_layers`）のロゴ画像でデフォルト画像の使用をオフにし、画像パスを `themes/custom/clear_layers/images/branding/jisaba-life-logo-v2.png` に設定します。

このロゴはライトモードでは元の青・紺・緑で、ダークモードでは CSS フィルターによって白く表示します。透明部分は維持し、OS の設定とサイトの表示切り替えに連動します。他のファイル名のロゴにはこのフィルターを適用しません。

ロゴだけを表示する場合は、ブランディングブロックの「サイトのロゴ」を有効にし、「サイト名」を無効にします。Canvas の共通ヘッダーを使っている場合は、そのパターン内のブランディングブロックで設定してください。既存サイトのロゴ設定や共通パターンは、テーマ更新だけでは変更しません。

## Canvas とページレイアウト

Canvas はテーマ単体の必須依存ではありません。Canvas で部品を編集する場合は Canvas を別途導入し、使う SDC をライブラリで有効にしてください。

テーマのインストールだけでは、ブログのコンテンツタイプ、Views、ページ、メニュー、Canvas テンプレートや共通パターンは作成されません。新規サイトでは、[Canvas 初期構成](#新規サイトの-canvas-初期構成)のボタンで共通パターンとページテンプレートを作成できます。記事本文・一覧カードのコンテンツテンプレートは Canvas 側で個別に設定します。

共通ヘッダー・フッターの参照部品（`shared-site-section`）は `site_header` と `site_footer` という ID の Canvas パターンを読み込みます。初期構成ボタンは、これらのパターンが未作成の場合に生成します。共通パターンを編集・公開すると、それを参照しているページに反映されます。ページ側の編集画面からは参照部品の設定にあるリンクで編集元を開きます。

フッターにログイン／ログアウトのリンクを追加する場合は、共通フッターのパターン内に **ログイン・ログアウトメニュー**（`account-menu`）を配置します。匿名時はログイン、ログイン中はログアウトを表示します。タイトルの上書き・表示・位置と、**ユーザーアカウント情報を表示**を設定できます。アカウント情報は初期状態で非表示です。オンにすると、アクセス権のある利用者にはアカウント情報へのリンクも表示します。Drupal 標準のアクセス制御とログアウトのトークンを使用し、サイトのメニュー設定は変更しません。

他のメニューは **フッターメニュー（タイトル設定）** の内側に標準メニューブロックを配置すると、同じタイトル設定とデザインを利用できます。標準ブロック自体のタイトル設定は Canvas では省略されます。標準メニューブロックの追加時に `Add a CSS class to ancestors of the current page` のエラーが出る場合は、内側のブロックで開始階層と表示階層をともに `1` にするか、そのチェック項目を有効にしてください。専用の `account-menu` 部品では、この階層フォームを使用しません。

初期構成で作るフッターメニューと、同梱補助モジュールが有効な Clear Layers サイトで新規追加する標準の **「フッター」** ブロックは、開始階層・表示階層の初期値をともに **1** にします。既存の配置で保存した表示階層は変更しません。他のメニュー名を持つ標準ブロックには、それぞれの設定を指定してください。

ヘッダーの専用 **「サイトナビゲーション」** は開始階層1・表示階層0（無制限）・全項目展開で描画します。これはメニューブロックの設定フォームを通さず、Canvas の階層フォーム検証の対象にはなりません。標準メニューブロックでの内部値 `null` も無制限を意味しますが、フッターの新規初期値には1を使います。

Canvas のプレビューでは、内側のメニューが入っていても親部品を選択できるよう、外側に **フッターメニュー（タイトル設定）** の帯と余白を表示します。帯をクリックしてタイトル設定を編集するか、左のレイヤー一覧から親部品を選択してください。この編集用の帯と余白は公開ページには表示しません。

`article-card` の任意の整数 prop `date` に記事の作成日時を渡すと、投稿日時を表示します。既存の日時なしの配置との互換性を維持しています。本文を `content-text` に渡すと、コードブロックを含む明暗モードのスタイルが適用されます。

初期設定と、任意のサイトデータの書き出し・導入については [starter-kit/README.md](starter-kit/README.md) を参照してください。実サイトのページ本文・構成図・設定の書き出しは、この公開リポジトリには含めていません。

## 開発

SDC ごとの Twig・CSS・JavaScript と、SCSS／JavaScript のソースを `components/` 内で管理します。Drupal の標準テンプレートは `templates/`、設定フォームは `theme-settings.php`、テーマの処理は `clear_layers.theme` にあります。

ビルドする場合はテーマディレクトリで実行します。Node.js の指定は `.nvmrc` を参照してください。

```sh
npm ci
npm run build
```

`npm run watch` のブラウザー連携を使う場合は `.env-example` を `.env` にコピーし、プロキシ先を開発環境に合わせて設定します。`.env` は Git で管理しません。

ビルド済みの CSS・JavaScript は配布に必要なため Git に含めます。`node_modules`、ソースマップ、ログ、バックアップ、AGENTS.md、実サイトの導入用データと個別移行スクリプトは `.gitignore` で除外しています。

明暗モードのソース検証:

```sh
node tests/color-scheme.mjs
```

Canvas のある Drupal サイトでのデータ診断（プロジェクト直下で実行）:

```sh
vendor/bin/drush php:script web/themes/custom/clear_layers/tests/canvas-health.php
```

インストール済みテーマの SDC と Twig の読み込み検証:

```sh
vendor/bin/drush php:script web/themes/custom/clear_layers/tests/theme-integrity.php
```

同梱背景画像の選択・プレビュー・保存値の検証（サイトの設定は保存しません）:

```sh
vendor/bin/drush php:script web/themes/custom/clear_layers/tests/background-picker.php
```

Core からコピーした標準テンプレートは Core 更新時に自動更新されません。`.info.yml` の `generator` を参照し、関連する Core の変更を確認して取り込んでください。公開済みの SDC の props／slots を変更する際は、Canvas の保存済みバージョンとの互換性を確認してください。
